# AI短剧生产链路

更新日期：2026-05-21

## 1. 总体定位

项目主线从“商业广告/产品宣传片”调整为“短剧生产工作流”，优先覆盖：

- 动漫短剧
- 真人短剧
- 抖音/快手/小红书竖屏短视频
- 虾仁漫剧、漫画解说、剧情号
- 后续可扩展到广告片、宣传片和影视级镜头

核心判断：

- ComfyUI 继续作为制作总控台。
- Wan2.2 系列负责角色、动作、画风、姿态控制。
- LTX-2.3 负责空镜、氛围、写实补镜头、质感增强和部分竖屏镜头。
- 非视频 API 负责剧本、角色图、关键帧、配音、字幕、包装、质检。
- 短剧的核心不是单条视频画质，而是角色一致性、画风一致性、动作可控、口型可控、批量生产可复用。

## 2. 总控架构

```text
Codex / LLM
  -> 剧本、分集大纲、镜头表、提示词、批处理脚本、质检清单

ComfyUI
  -> Wan2.2 / LTX-2.3 / HunyuanVideo / LivePortrait 等生成与后期节点

素材与模型资产库
  -> 角色设定图、表情表、服装表、场景图、动作参考视频、音频、字幕

剪辑与交付层
  -> FFmpeg / 剪辑软件 / HyperFrames / 字幕包装 / 多平台导出
```

## 3. 模型资产计划

### 3.1 第一批计划下载

短剧主线优先下载以下模型，全部优先 FP8 / fp8_scaled / Kijai FP8，不优先 BF16/FP16：

| 模型 | 精度 | 主要用途 | 优先级 |
| --- | --- | --- | --- |
| Wan2.2-Animate-14B | FP8 KJ | 角色动画、角色替换、动作/表情复刻 | P0 |
| Wan2.2 Fun Control | FP8 scaled | OpenPose/Canny/Depth/轨迹控制，动作可控 | P0 |
| Wan2.2-I2V-A14B | FP8 / GGUF | 关键帧图生视频、角色镜头 | P0 |
| Wan2.2 Fun Inp / FLF2V | FP8 scaled | 首尾帧过渡、镜头衔接 | P1 |
| Wan2.2-T2V-A14B | FP8 scaled | 空镜、场景、剧情环境 | P1 |
| LTX-2.3 22B dev | FP8 | 空镜、氛围、写实补镜头、质感增强 | P0 已在部署 |

### 3.2 LTX-2.3 所需文件

ComfyUI/models/checkpoints/

### 3.3 不作为当前主线的版本

- Wan2.2 14B BF16/FP16：48GB 可尝试但不适合作为第一阶段生产主线，显存和速度压力较大。
- Wan2.2 4-step / Lightning / step-distill：后续用于快速草稿，不作为质量主线。
- LTX-2.3 distilled：后续用于快速试错，不作为当前主质量模型。
- S2V-14B：对口型和音频驱动很重要，但 48GB 可能吃紧；先等 Animate / Fun Control 跑通后再接入。

## 4. 五条生产链路

### 链路 1：动漫短剧 / 虾仁漫剧主链路

目标：

- 制作 9:16 竖屏动漫短剧、虾仁漫剧、漫画剧情号。
- 保持 2D 角色画风、人设、服装、脸型、表情稳定。
- 支持眨眼、说话、回头、抬手、走路、争吵、惊讶等常见短剧动作。

输入：

- 剧本片段、分镜表、对白。
- 角色设定图：正面、侧面、半身、全身、表情表。
- 场景图：房间、学校、办公室、街道、玄幻场景等。
- 动作参考视频或姿态序列。
- 配音音频或待配音文本。

核心工具：

- LLM/Codex：剧本、镜头表、提示词、批量任务。
- GPT Image 2 / AsymFlow / SD 系工具：角色图、表情图、场景图、首尾帧。
- Wan2.2-Animate-14B FP8：角色动作、表情复刻、角色替换。
- Wan2.2 Fun Control FP8：姿态、轨迹、动作控制。
- Wan2.2-I2V-A14B FP8：关键帧动起来。
- Wan2.2 Fun Inp / FLF2V：首尾帧衔接。
- LivePortrait / Just-Dub-It / Wan2.2-S2V：口型、眨眼、表情微动。
- HyperFrames：字幕、气泡、片头、转场、抖音包装。

流程：

```text
剧本
  -> 分集大纲
  -> 镜头表
  -> 角色设定图 / 表情表 / 场景图
  -> 关键帧和首尾帧
  -> Wan2.2 I2V / Animate / Fun Control 生成镜头
  -> 口型和表情微调
  -> 字幕、气泡、片头包装
  -> 剪辑合成与导出
```

验收指标：

- 同一角色跨镜头脸型、发型、服装、画风一致。
- 每条镜头 5-8 秒优先，先稳定再延长。
- 竖屏 9:16，优先 512x896 / 576x1024 起步，后续上采样。
- 口型和语音节奏基本对齐。
- 画面不明显 3D 化、真人化、脸漂或服装漂。

常见失败与补救：

- 脸漂：加强角色参考图、改用 Animate / I2V、降低动作幅度。
- 画风崩：减少写实词，强化 2D/anime/cel shading 风格，固定角色图。
- 动作不对：使用 Fun Control / pose video，不只靠提示词。
- 口型差：先生成静态/轻动作视频，再用 LivePortrait / S2V 补口型。

### 链路 2：真人短剧 / 写实短剧链路

目标：

- 制作真人短剧、写实剧情号、口播剧情、带对白的短视频。
- 重点解决锁脸、表情自然、口型同步、光影统一。

输入：

- 真人角色参考图或授权肖像素材。
- 剧本对白、分镜表。
- 动作参考视频、口播音频。
- 场景图或真实素材。

核心工具：

- HunyuanVideo-1.5：真人/写实 I2V、补镜头、超分候选。
- LTX-2.3：写实空镜、氛围、竖屏镜头、质感增强。
- Wan2.2-Animate Replace：角色替换和动作复刻。
- InstantID / PuLID / IP-Adapter Face / 换脸修复：身份一致性层。
- Gemini TTS / Just-Dub-It / LivePortrait：对白、口型、表情。
- Relit-LiVE / LTX HDR LoRA：重新布光、HDR、调色前处理。

流程：

```text
真人角色设定
  -> 分镜和对白
  -> 关键帧锁脸
  -> Hunyuan / LTX / Wan Animate 生成镜头
  -> 身份一致性修复
  -> 口型同步
  -> 光影统一和调色
  -> 剪辑合成
```

验收指标：

- 主角跨镜头五官稳定。
- 口型与对白节奏对齐。
- 表情自然，没有明显塑料脸、融脸、眼神漂。
- 多镜头光影、肤色和服装一致。

常见失败与补救：

- 脸不像：先修关键帧，必要时逐帧/分段换脸修复。
- 口型不准：先用短句，分句生成，减少长音频一次驱动。
- 真人动作假：使用真实动作参考视频或 Animate replacement。

### 链路 3：空镜 / 氛围 / 运镜链路

目标：

- 生成短剧中的城市、校园、办公室、玄幻、悬疑、转场、环境镜头。
- 不承担角色锁脸，专注镜头语言、光影、气氛、场景建立。

输入：

- 场景设定、时代背景、情绪基调。
- 镜头语言：推、拉、摇、移、环绕、航拍。
- 参考图、风格图、首尾帧。

核心工具：

- LTX-2.3：氛围、写实空镜、竖屏电影感。
- Wan2.2-T2V-A14B：场景生成和剧情环境。
- Wan2.2 Fun Camera：可控运镜。
- Warp-as-History：精确轨迹控制。
- Prompt Relay：大跨度场景转场。
- LTX HDR LoRA / Relit-LiVE：调色前处理和布光统一。

流程：

```text
场景需求
  -> 场景参考图
  -> 镜头运动设计
  -> LTX / Wan T2V / Fun Camera 生成
  -> 转场或首尾帧控制
  -> HDR / relight / 调色
  -> 插入短剧剪辑线
```

验收指标：

- 运动自然、无明显抖动、无莫名主体变形。
- 与角色镜头风格一致。
- 能承担叙事功能：建立地点、制造情绪、连接镜头。

常见失败与补救：

- 运镜乱：改用 Fun Camera / Warp-as-History。
- 场景不连续：使用首尾帧或 Prompt Relay。
- 画面太空：补充前景、中景、景深和光源描述。

### 链路 4：配音 / 口型 / 出海链路

目标：

- 建立短剧音频生产线，支持中文、英文及多语言版本。
- 让角色对白、旁白、字幕、口型和剪辑节奏统一。

输入：

- 剧本对白、旁白稿、多语言翻译稿。
- 角色音色设定或授权声音样本。
- 已生成视频片段或角色图。

核心工具：

- Gemini 3.1 Flash TTS / 高质量 TTS：旁白和角色对白。
- VoxCPM2：中文/多语 TTS 候选。
- xAI 声音克隆：只在授权明确时使用。
- Just-Dub-It：多语言配音和口型同步。
- LivePortrait：动漫/真人头像口型、眨眼、表情微动。
- Wan2.2-S2V：音频驱动视频候选，等主链路稳定后接入。
- HyperFrames：字幕、标题、信息流包装。

流程：

```text
对白脚本
  -> 分句和情绪标注
  -> TTS 生成音频
  -> 音频清理和节奏调整
  -> 口型驱动 / 表情驱动
  -> 字幕生成与包装
  -> 多语言版本导出
```

验收指标：

- 每句对白可独立替换和重生成。
- 口型大致对齐，不抢拍、不拖拍。
- 情绪、语速、音色符合角色设定。
- 出海版本字幕、配音和画面节奏一致。

常见失败与补救：

- 长句口型难对：按短句切分，逐句驱动。
- 情绪平：在 TTS 阶段增加情绪标签和语速控制。
- 字幕遮挡：使用固定安全区和短视频字幕模板。

### 链路 5：拉片 / 质检 / 复盘链路

目标：

- 用优秀短剧和爆款短视频反推镜头节奏。
- 对生成成片做角色、画风、动作、音频、字幕、平台规格质检。
- 把经验沉淀成模板，而不是每次从零试错。

输入：

- 参考短剧、广告、爆款短视频。
- 已生成视频片段。
- 镜头表、提示词、参数、模型版本。

核心工具：

- OmniShotCut：剪切点、转场类型、镜头节奏识别。
- LLM/Codex：反推镜头表、节奏表、质检报告。
- 图像/视频理解 API：识别穿帮、角色漂、字幕遮挡。
- FFmpeg：抽帧、转码、拼接、批量生成预览。

流程：

```text
参考片
  -> OmniShotCut 拉片
  -> LLM 反推镜头结构
  -> 生成镜头模板
  -> 成片抽帧和节奏分析
  -> 质检报告
  -> 修复清单
  -> 模板沉淀
```

验收指标：

- 每条成片有镜头表、模型版本、提示词、参数和输出路径。
- 每个失败镜头能归因到角色、动作、画风、口型、字幕或剪辑问题。
- 每次测试至少沉淀一个可复用模板。

常见失败与补救：

- 不知道为什么不好看：先拉片，再按镜头节奏重做。
- 多条镜头风格散：统一角色图、场景 LUT、字幕模板和提示词结构。
- 废片太多：记录失败标签，减少重复试错。

## 5. 第一阶段执行顺序

当前不要同时展开五条链路，先按以下顺序验证：

1. 保留并跑通 LTX-2.3 22B dev FP8，作为空镜/氛围/补镜头能力。
2. 扩容数据盘到至少 500GB，短剧模型和输出会迅速增长。
3. 下载并部署 Wan2.2-Animate-14B FP8 KJ。
4. 下载并部署 Wan2.2 Fun Control FP8 scaled。
5. 下载并部署 Wan2.2-I2V-A14B FP8 / GGUF。
6. 生成第一条 5 秒竖屏动漫短剧测试镜头：
   - 固定角色
   - 2D 画风
   - 眨眼或说话
   - 轻微动作
   - 画风不崩
7. 成功后再补 Fun Inp / FLF2V 和 T2V-A14B。

## 6. 第一条测试镜头规格

目标：

```text
5 秒 9:16 竖屏动漫短剧镜头
角色：固定单人角色
场景：室内或校园走廊
动作：眨眼、开口说一句台词、轻微转头或抬手
风格：2D anime / cel shading / clean line art
输出：低分辨率先跑通，后续再上采样
```

首轮验收只看四件事：

- 角色是否稳定。
- 画风是否保持 2D。
- 动作是否可控。
- 是否能进入配音/字幕流程。

## 7. 记录规范

每条镜头必须记录：

- 剧集/镜头编号
- 模型和版本
- 工作流 JSON 路径
- 输入素材路径
- 分辨率、帧数、fps、steps、seed
- 生成耗时、显存占用
- 输出路径
- 失败原因和修复建议

禁止提交到 Git：

- 模型权重
- 输出视频
- 缓存
- API key / token / SSH 密码
- 未授权真人素材
