# LTX-2.3 FP8 生产路线

更新日期：2026-05-20

## 1. 路线定位

本项目从 Wan2.2 TI2V 5B 基线测试切换为：

```text
ComfyUI 生产总控台
  -> LTX-2.3 FP8 / Distilled 作为开源视频主力
  -> HunyuanVideo-1.5 I2V 作为稳定产品镜头补充
  -> SkyReels-V2 作为长镜头/连续叙事补充
  -> 非视频 API 负责图片、文案、分镜、TTS、音乐、字幕、设计规范
  -> FFmpeg / 剪辑软件完成合成、调色、转码和交付
```

目标不是单模型炫技，而是形成低成本、可复现、可迭代的商业视频生产线，覆盖影视、漫剧、广告、宣传片和外贸产品视频。

## 2. 服务器选择

首选实例：

- GPU：vGPU-48GB-350W / 48GB
- 内存：90GB
- CPU：12 核或以上
- 数据盘：当前 200GB；后续如同时保留多模型和批量输出，推荐扩到 300-500GB
- 系统：Ubuntu 22.04
- 镜像：PyTorch 2.7.0 / Python 3.12 / CUDA 12.8

选择理由：

- LTX-2.3 官方建议 ComfyUI 场景至少 32GB+ VRAM，48GB 比 24GB 4090D 更适合生产。
- FP8 与蒸馏模型可以降低显存压力，用于快速迭代。
- 48GB 不等于满血 H100/A100，但已经足够支撑 LTX-2.3 的商业镜头生产尝试。

## 3. LTX-2.3 模型策略

优先级：

1. LTX-2.3 22B dev FP8：当前主力，优先用于商业镜头生产。
2. LTX-2.3 22B distilled FP8：后续可选，用于快速批量试错。
3. 上采样/超分工作流：用于最终交付前提升质感。
4. BF16 全量模型：只在 48GB 能稳定运行且质量明显提升时使用；否则不作为第一阶段主线。

官方约束：

- 宽高需要能被 32 整除。
- 帧数需要满足 `8n + 1`，例如 41、49、57、65、73、81、97、121。
- 推荐先低分辨率、少帧、少步数验证，再提高规格。

## 4. 非视频 API 分工

视频 API 暂不作为主力，避免成本失控。非视频 API 可以增强生产质量：

- LLM：创意方向、脚本、分镜、镜头提示词、质检清单。
- 图片生成 API：产品主视觉、首帧、尾帧、关键帧、风格图、海报图。
- TTS API：旁白、角色对白、不同语言配音。
- 音乐/音效 API：广告背景音乐、环境音、转场音效。
- 图像理解 API：分析参考图、产品卖点、画面缺陷。
- 翻译/本地化 API：外贸广告多语言版本。

关键原则：

- 产品广告镜头优先走 I2V / keyframe / reference-to-video，不把纯 T2V 作为产品外观一致性的唯一来源。
- 非视频 API 生成的是素材和控制信息，视频主体仍由开源模型生成。

## 5. LTX 主线增强组件

以下工具/能力最值得优先与 LTX-2.3 22B dev FP8 搭配，目标是提升成片质量，而不是替换 LTX 主模型。

| 组件 | 角色 | 优先级 | 说明 |
| --- | --- | --- | --- |
| GPT Image 2 / 高质量图片 API | 关键帧、首帧、尾帧、产品主视觉、海报图 | P0 | 产品广告必须先把参考图做稳，再交给 LTX 做 I2V/镜头运动。 |
| HyperFrames | 片头、字幕包装、产品卖点动画、网页/组件动画转视频 | P0 | 非常适合广告片、宣传片、产品参数展示和高级感转场包装。 |
| Gemini 3.1 Flash TTS / 高质量 TTS | 多语言旁白、广告配音、角色情绪对白 | P0 | 用于影视、漫剧、外贸广告出海。声音部分不要等视频链路全部完成后才考虑。 |
| LTX HDR LoRA | HDR、调色前处理、EXR/高动态范围后期 | P1 | 跑通 LTX 主链路后接入，用于提升后期调色空间和商业质感。 |
| Just-Dub-It | 人像/口播/短剧多语言配音和口型同步 | P1 | 适合真人/角色镜头、短剧翻译、出海配音；产品广告优先级低于 TTS。 |
| Warp-as-History | 精确运镜控制 | P1 | 当 LTX 原生运镜不够稳定时，用于轨迹约束和复杂镜头运动补充。 |
| Relit-LiVE | 视频重新布光 | P1 | 用于修正生成后光照、统一多镜头打光和提升广告质感。 |
| OmniShotCut | 拉片分析、剪切点/转场识别、节奏参考 | P1 | 用于分析优秀广告/短剧样片，反向生成镜头表和剪辑节奏。 |
| AsymFlow | 真实感参考图/关键帧生成 | P2 | 作为图片级关键帧增强候选，先不影响 LTX 主部署。 |
| Pixar-Style CGI Toon LoRA | 漫剧/卡通风格参考图和角色图 | P2 | 适合漫剧、动画广告，不用于真实产品广告主线。 |

短期接入顺序：

```text
LTX-2.3 跑通
  -> GPT Image 2 / 图片 API 生成参考图
  -> HyperFrames 做包装动画
  -> Gemini TTS 做旁白
  -> LTX HDR LoRA / Relit-LiVE / Just-Dub-It 进入后期增强
```

## 6. 后续探索玩法

以下工具先记录为探索方向，不进入第一阶段部署，避免主线复杂度爆炸。

| 工具 | 探索价值 | 暂不优先原因 |
| --- | --- | --- |
| HappyHorse-1.0 | 可能是强视频/音视频模型候选 | 需要进一步核验官方权重、许可证、本地部署成熟度和 ComfyUI 接入情况。 |
| Prompt Relay | 大跨度场景无缝转场思路 | 先借鉴提示词接力方法，暂不作为独立部署模块。 |
| ODYSSEY Odyssey-2 Max | 交互式世界模型、无限时直播剧情 | 平台型/闭源倾向较强，不适合作为当前低成本自建主线。 |
| SpAItial Echo-2 | 照片到交互式 3D 场景 | 更偏空间/世界模型，后续用于场景资产探索。 |
| Netflix Vista4D | 4D 重拍、视频后期可编辑 | 更适合已有视频重构和高级后期，不是从零广告片主生成器。 |
| SANA-WM | 一张图生成可探索 3D 世界 | 适合影视场景和世界探索，后续再评估。 |
| Moonlake 3D Agent | Blender 建模和资产迭代 | 等视频主链路稳定后，再接入 3D 资产生产。 |
| Claude 创作软件连接器 | Photoshop、Blender、Ableton 等创作软件自动化 | 需要额外平台权限和软件环境，先不进入第一阶段。 |
| Google 视觉设计规范技能 | 品牌 UI/视觉规范输出 | 可用于品牌手册和包装规范，暂不阻塞视频生成主链路。 |
| xAI 声音克隆 | 多语言声音克隆 | 涉及授权、隐私和商业合规，必须谨慎使用。 |

原则：除非某个探索工具能明显解决当前 LTX 链路的痛点，否则不在第一阶段同时安装多个重模型。

## 7. 第一阶段交付目标

切换服务器后，第一阶段只做三条可交付镜头：

1. 外贸玻璃鸟类产品广告镜头：产品转台、反光、展厅、品牌质感。
2. 太阳灯类产品广告镜头：户外庭院、日夜变化、灯光亮起。
3. 首饰类目广告镜头：珠宝特写、微距、镜头推近、闪光细节。

每条镜头要求：

- 5-10 秒。
- 至少 720p 生产母版或 480p 生成后高质量上采样。
- 保存工作流 JSON、提示词、参数、模型版本、耗时、显存占用和输出路径。
- 输出视频不提交 Git，只保存在本地和服务器数据盘。

## 8. 部署原则

- 所有大文件放在数据盘，例如 `/root/autodl-tmp/AI-Video-LTX`。
- 使用 `screen` 或 `tmux` 执行模型下载和长时间生成。
- 不把模型、输出视频、缓存放进 Git 仓库。
- 下载优先使用官方 Hugging Face；如果速度慢，再使用镜像或断点续传。
- 先跑官方 ComfyUI 示例工作流，再改造成我们的商业镜头模板。
